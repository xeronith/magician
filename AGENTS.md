# AGENTS.md

`magician` is a tiny Go CLI and HTTP API, and a demo of a prompt-driven SDLC pipeline.
`README.md` explains the design, setup, and risks. This file only covers what an agent
needs to change the repo without breaking it.

## The app is generated from the spec

- `PROMPT.md` is the source of truth. `cmd/`, `docs/`, and `go.mod` are produced by the
  `implement` job; the repo started as the pipeline and the app was generated by it.
- When changing user-facing behavior locally, edit `PROMPT.md` **and** the generated files
  in the same change. A later push that only touches `PROMPT.md` re-runs the implementer,
  so behavior that exists only in code can be lost. The CI implementer only reads
  `PROMPT.md`; it is denied edits to it.
- Locally, a CLI command touches `PROMPT.md`, `cmd/magician/main.go`, `main_test.go`, and
  `docs/usage.md`. An HTTP change also touches `server.go`, `server_test.go`, and
  `openapi.json`. In CI the implementer edits the generated files because the prompt
  change triggered the run.

## Verification commands

Run in this order; it matches the `implement` job.

```sh
GOFMT="$(go env GOROOT)/bin/gofmt"
"$GOFMT" -w .
go mod tidy
go build ./...
go build -o magician ./cmd/magician
go vet ./...
go test ./...
go run github.com/golangci/golangci-lint/v2/cmd/golangci-lint@v2.15.0 run ./...
```

- **`gofmt` is often not on `PATH`** on this machine. Always use
  `"$(go env GOROOT)/bin/gofmt"`, as the workflow does.
- **Use golangci-lint v2.15.0**, the version CI pins. A stock local v1.x binary fails
  against Go 1.26 with `unsupported version: 2`.
- Single test: `go test ./cmd/magician -run TestGreeting -v`
- The module has no dependencies and no `go.sum`; stay on the standard library.

## Code conventions

- Entrypoint is `./cmd/magician`, package `main`, and must keep `var version = "dev"`.
  Releases inject the tag with `-ldflags "-X main.version=<tag>"`.
- Command logic goes through `run(io.Writer, []string) error`; `main` only wires
  `os.Args` and the exit code. Tests call `run` with a `bytes.Buffer`.
- Tests are table-driven and fast: no external network, sleeps, or external services.
  HTTP tests use `net/http/httptest` and never bind a fixed port.
- `errcheck` is enabled. Return errors, or discard them explicitly with `_, _ =`
  (see `say`). Don't leave a bare `fmt.Fprintln(...)`.
- `docs/usage.md` must document every user-facing command, endpoint, and exact output.

## HTTP server

- `magician serve` lives in `cmd/magician/server.go`, defaults to `127.0.0.1:8080`, and
  blocks until interrupted. Keep the existing CLI commands in `main.go` working.
- `newSpellHandler()` returns the full mux so tests can use `httptest` without binding a
  port. Never fetch the Scalar CDN or sleep in tests.
- The spell store is in-memory and mutex-guarded; IDs increase from 1 and are never reused.
- `cmd/magician/openapi.json` is embedded with `//go:embed` and must stay in sync with the
  routes. `/docs` imports
  `https://cdn.jsdelivr.net/npm/@scalar/api-reference@1.77.0/esm.js` in the browser and
  points Scalar at `/openapi.json`.
- Default to loopback. The server has no auth, TLS, persistence, or rate limiting; don't
  expose it beyond `127.0.0.1` in examples without calling that out.

## Pipeline rules

- **A `PROMPT.md` push to `main` is a release action.** The workflow only triggers for
  pushes that change `PROMPT.md`; every green run publishes `v0.1.<run_number>`. The
  implementer may open `sdlc/run-<n>-<attempt>`, which is squash-merged if the review
  approves.
- Pushes that don't touch `PROMPT.md` do not trigger the workflow at all. No agent,
  lint/tests, or release runs for them. `workflow_dispatch` always runs the implementer.
- The CI implementer may not modify `.github/**`, `.opencode/**`, `PROMPT.md`,
  `opencode.json`, or `README.md`; the workflow re-checks this with `git status` and
  fails the run before committing. It also cannot run `git commit`, `git push`, or `gh`.
- The reviewer is read-only except for `REVIEW.md`; it must start with exactly
  `VERDICT: APPROVE` or `VERDICT: REQUEST_CHANGES`. The workflow parses only the first
  five lines and fails closed on anything else. Don't commit `REVIEW.md`.
- The implementer's task instructions live in `.github/sdlc/implement.md`; its permissions
  live in `.opencode/agents/implementer.md`. Changing behavior requires editing the first;
  changing allowed actions requires the second.
- `opencode.json` denies reading `*.env` files for every agent, so don't rely on `.env`
  secrets in local sessions.

## CI-specific quirks

- OpenCode is pinned to `2.2.6` and installed from `https://opencode.ai/v2/install`.
  The older `/install` URL rejects V2 versions.
- Both agent steps use `opencode --standalone`. The shared background service caches
  config and env, so without `--standalone` `{env:LITELLM_BASE_URL}` and
  `{env:SDLC_MODEL}` can resolve empty.
- Model config comes from the `SDLC_MODEL` repository variable and the
  `LITELLM_BASE_URL` / `LITELLM_API_KEY` secrets. The model must support tool calling.
- When editing `.github/workflows/sdlc.yml`, validate with:
  `go run github.com/rhysd/actionlint/cmd/actionlint@latest .github/workflows/sdlc.yml`
- Actions are pinned to Node 24 majors (`checkout@v7`, `setup-go@v7`, `cache@v6`,
  `upload-artifact@v7`) and every job uses `ubuntu-24.04`. Don't use `ubuntu-latest` or
  Node 20 action majors; they produce deprecation warnings. Node 24 actions need runner
  `v2.327.1+`, which GitHub-hosted runners satisfy.
- Keep the `implement` and `quality` jobs on matching tool versions (Go `stable`,
  golangci-lint `v2.15.0`) and keep `.github/sdlc/implement.md` telling the agent to run
  the same commands.
